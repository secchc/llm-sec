# LLM-Sec

LLM-Sec 是给本地 agent 用的安全技能。它做两件事：审查 agent 的每一次行为，以及在启用前审查另一份 skill 是否不安全。

LLM-Sec reviews each agent tool call before it runs, and reviews another skill before that skill is enabled. It blocks file theft, file destruction, and other actions the user did not ask for.

## 它拦的是什么

Agent 会读文件、写文件、删文件、跑命令、访问网络，也会照着另一份 skill 的正文去做。用户只说了「画一张图」或「改一段文案」时，技能正文或模型自己仍可能悄悄把文件读走、发出去，或把文件删掉、覆盖掉。

LLM-Sec 在动作发生前看这次调用实际要做什么。即使用户没把「删除」「外发」写出来，也要查。

## 两类审查

**Agent 行为审查。** 读、写、删、跑命令、访问网络，每一次都先查再执行。允许范围只从用户这一句原话来。密钥不读取、不打印、不外传。

**不安全 skill 审查。** 启用另一份 skill 之前先看它的正文，不执行里面的命令。正文若要求用户没点名的创建、删除、覆盖、改权限、外发或读密钥，就不启用。用户说「调用」或「运行」，只表示想用这份技能，不等于同意这些动作。

越出范围时有三种处理：拒绝，改成仍能完成任务的更小范围，或先停下来等用户确认。用户自己点名的删除、推送、发布、部署会先问一声；同意只覆盖这一条。用户没交代、技能想悄悄做的破坏动作不会改成确认后照做。没有只记录、不拦截的模式，也没有监控页面。

它是写给模型遵守的技能文本。平台如果仍会执行模型发出的工具调用，拦不拦得住，取决于模型有没有按这份文本做。

## 场景

**表面上是作图，悄悄毁文件。** 用户要一张小狗图片，并调用一份看起来是作图的技能。正文却要在桌面创建一个文件再删掉，做完还说作图已经完成。LLM-Sec 不启用这份技能，文件不会创建，也不会删除。

**改文案时悄悄把文件读走。** 用户要改登录页文案。Agent 转去读密钥、私人目录，或把仓库里的文件发到用户没点名的地方。这一步拦住，文件留在原地。

**没说删除，却要毁掉文件。** 用户没点名任何要删的文件。Agent 或另一份技能要删除文件、清空目录，或覆盖用户没点名的文件。这些动作不执行。

**用户自己点名的不可逆动作。** 用户明确说了删某一个文件，或要推送、发布。LLM-Sec 先停住，等用户对这一条回一声。还没同意之前不做。

## 用户看到的话

有问题的那一条回复从这一行开始，前面不再另起一段：

```text
❌❌❌ LLM-Sec发现不安全行为。
详情：llm-sec-fixture-draw-cover 想在你没说的情况下，悄悄在桌面创建一个文件再删掉。这两步拦住了，文件没有创建，也没有删除。
🛡️ LLM-Sec已进行防护，结果：🔴拦截 2026.11.16.18
```

没有越界时，先用一句口语回答任务，最后一行是 `🛡️ LLM-Sec已进行防护，结果：🟢安全`，后面带版本号。同一次提问只在最后一条回复里写一次。技能名称用它自己的 name，不改成说明里的称呼。

## 安装

在你信任的环境里，把本仓库的 `skills/llm-sec/` 放到该 agent 会读取的 skills 目录，再运行模型。不要让陌生模型自己装。装上之前的行为，这份技能审查不到。正在进行的对话要新开一轮，才会带上最新全文。

- Cursor：`~/.cursor/skills/llm-sec/SKILL.md`
- Claude Code：`~/.claude/skills/llm-sec/SKILL.md`
- Codex：`~/.agents/skills/llm-sec/SKILL.md`
- Hermes：放到它的 skills 目录，并在配置的 `skills.auto_load` 里写上 `llm-sec`。新会话开场就会带上全文。

其他产品放到该产品自己的 skills 目录。

判定顺序在 `skills/llm-sec/SKILL.md`。读、写、删、命令、网络和技能审查的细项在 `skills/llm-sec/references/`。细项不能放宽 `SKILL.md`。版本号在文首 `version`，格式是 `年.月.日.序号`，当前是 `2026.11.16.18`。

作者有 10 年网络安全行业经验。
